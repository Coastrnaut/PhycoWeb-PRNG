1. Executive Summary & Design Paradigm


1.1 High-Level Overview

> **Status (2026-10-28): experimental research generator. Not for secrets.** PhycoWeb-PRNG has no
> cryptographic analysis or review. It must not be used to generate keys, nonces, tokens, salts or
> any other secret; use an established cryptographic RNG instead (e.g. the operating system's
> CSPRNG). Statistical-test results, including NIST SP 800-22, do not show cryptographic security.
> See section 5 for what has and has not been verified.

PhycoWeb-PRNG is an experimental hardware-oriented generator design that moves away from traditional mathematical abstractions—such as Linear Congruential Generators (LCGs) or standard Artificial Neural Networks (ANNs)—and looks instead to organic systems. It models the decentralized, non-linear foraging behavior of slime molds (Physarum polycephalum) and fungal mycelium networks.
```text
       [ Food Signal A ]              [ Food Signal B ]
               │                              │
               ▼                              ▼
      ┌────────────────┐             ┌────────────────┐
      │  Grid Node 00  │════════════>│  Grid Node 01  │
      └────────────────┘             └────────────────┘
               ║                              ▲
               ║ (Dynamic Vein Thickness)      │ (Feedback)
               ▼                              │
      ┌────────────────┐             ┌────────────────┐
      │  Grid Node 10  │════════════>│  Grid Node 11  │
      └────────────────┘             └────────────────┘
               │                              │
               └──────────────┬───────────────┘
                              ▼
                     [ Slicing Engine ]
                              │
                              ▼
                  [ 32-bit Output Word ]
```

There is no whitening or cryptographic post-processing stage. The output word is taken directly
from the grid state (feature 002 forbids adding one).
Instead of processing values through layers of rigid arithmetic, the network maintains a parallel, self-routing grid of interconnected Node Points. These node connections adjust their internal configurations based on fluid-dynamic models of nutrient transportation. The design intent is that deliberately frustrating this network with structured environmental disruptions ("Frustrated Foraging") keeps it from settling into a stable pattern, and that the output words taken from its state are statistically well distributed. These are design goals, not established properties. The generator is deterministic: its output is fully determined by the seed. It has not been shown to be chaotic, high-entropy or unpredictable, and it is **not** cryptographically secure (section 5).

1.2 Mathematical Foundations of Bio-Fluidic Chaos

The architecture tracks two primary integer vectors across time: Nutrient Pressures (P) bound to localized coordinates, and Vein Thicknesses (D) representing structural transmission channels. The flow rate or nutrient flux (Q) traveling across a channel connecting node i to node j is governed by a discrete approximation of Poiseuille's Law:
\(Q_{ij}(t)=\frac{D_{ij}(t)\cdot \left(P_{i}(t)-P_{j}(t)\right)}{L}\)
Channel dimensions dynamically adapt based on usage. Active channels grow thicker through reinforcement, while unused paths contract over time due to constant decay:
\(D_{ij}(t+1)=D_{ij}(t)+\alpha \cdot |{}Q_{ij}(t)|{}-\gamma \cdot D_{ij}(t)\)
To prevent the web from settling into a stable, repeating shortest-path bridge, a threshold supervisor monitors channel scale metrics. When a channel crosses the critical saturation limit (\(D_{ij} > \tau\)), it triggers a localized XOR disruption on adjacent nodes. This shatters the established network paths and forces the system to start foraging anew. (In the feature-001 model `lut-v1`, this disruption fires on about 99.5% of steps, so it is effectively always on. In the feature-002 model `phyco-v2` it fires on 13.5–13.8% of steps, within the required 1–50%.)

2. Complete Bit-Accurate Python Verification Model

The integer reference model lives in `phycoweb/model.py`, with its perturbation table in `phycoweb/lut.py` (generated by `scripts/gen_lut.py`; spec `specs/001-integer-lut-perturbation`). It is integer-only and is the golden model for a future VHDL implementation (RTL-pending). The previous floating-point listing is archived at `baseline/float-v0/readmee_model.py`. Current `phycoweb/model.py`:
```python
"""PhycoWeb-PRNG bit-accurate integer reference model, `lut-v1`.

Spec: specs/001-integer-lut-perturbation (FR-007b/c perturbation, FR-008a other stages).
Experimental deterministic generator; not suitable for generating secrets.
"""
from typing import List, Sequence, Tuple

from phycoweb.lut import COS_OFFSET, INC_A, INC_B, PERTURBATION_LUT

MODEL_ID = "lut-v1"

_CHANNELS = ((0, 1), (1, 2), (2, 3), (3, 0))


def wrap32(x: int) -> int:
    """Wrap to 32-bit two's complement, matching numpy int32 overflow (research R1)."""
    return ((x + 0x80000000) & 0xFFFFFFFF) - 0x80000000


class PhycoWebEngine:
    def __init__(self, seed: Sequence[int]) -> None:
        if len(seed) < 4:
            raise ValueError("seed must contain at least 4 values")
        for value in seed[:4]:
            if type(value) is not int or not 0 <= value <= 0xFFFF:
                raise ValueError(f"seed values must be ints in 0..65535, got {value!r}")
        self.P: List[int] = list(seed[:4])
        self.D: List[int] = [256, 256, 256, 256]
        self.phase_a = 0
        self.phase_b = 0
        self.step_count = 0

    def _perturb(self) -> Tuple[int, int]:
        """Stages 1-4 (FR-007c): advance phases, read the table, inject food."""
        self.step_count += 1
        self.phase_a = (self.phase_a + INC_A) & 0xFF
        self.phase_b = (self.phase_b + INC_B) & 0xFF
        food_a = PERTURBATION_LUT[self.phase_a]
        food_b = PERTURBATION_LUT[(self.phase_b + COS_OFFSET) & 0xFF]
        self.P[0] = (self.P[0] + food_a) & 0xFFFF
        self.P[2] = (self.P[2] + food_b) & 0xFFFF
        return food_a, food_b

    def compute_block(self) -> int:
        self._perturb()
        P, D = self.P, self.D

        # Stage 5, flux. The variable product and its 32-bit wrap are existing behavior kept
        # deliberately (FR-008a); see spec Open Issues 1 and 2.
        Q = [wrap32(D[i] * (P[i] - P[j])) >> 8 for i, j in _CHANNELS]

        # Stage 6, growth and decay.
        for k in range(4):
            growth = wrap32(abs(Q[k])) >> 2
            D[k] = (D[k] + growth - (D[k] >> 4)) & 0xFFFF
            if D[k] == 0:
                D[k] = 1

        # Stage 7, Frustrated Foraging disruption.
        if D[0] > 4096 or D[2] > 4096:
            P[1] ^= 0x5A5A
            P[3] ^= 0xA5A5

        # Stage 8, harvest (unsigned 32-bit word).
        return ((D[0] & 0xFF) << 24) | ((D[1] & 0xFF) << 16) | ((D[2] & 0xFF) << 8) | (D[3] & 0xFF)
```

3. Hardware Implementation Strategy & RTL Mapping

This section describes the **hardware design targets**. No RTL exists yet (RTL-pending), so none of these targets has been synthesized or measured. Where the current reference model (`lut-v1`) does not yet meet a target, this is stated.

3.1 Multiplierless Integer Domain Optimization

Floating-point arithmetic introduces significant latency and resource overhead. The target is integer-only arithmetic with fractional scaling done by constant bit-shifts (>> 4 for a division by 16, >> 8 for a division by 256), so that no multipliers or dividers are needed. The current model `lut-v1` is integer-only, but it is **not yet multiplierless**: its flux stage multiplies two state variables (`D[i] * (P[i] - P[j])`), and that intermediate needs 32 bits. P and D are unsigned 16-bit values, not signed. Removing the multiplier is the subject of feature 002 (`specs/002-core-dynamics-redesign`); its model `phyco-v2` (`phycoweb/model_v2.py`) is integer-only and multiplierless, with 32-bit pressures and veins.

3.2 Highly Parallel, Decentralized Logic Distribution

The target is that each channel node communicates only with its direct neighbours on the grid, with no long global signal lines, so that the grid can scale to larger configurations (such as 8×8 or 16×16) without timing bottlenecks. The current model `lut-v1` is a fixed 4-node ring. Its disruption rule reads two nodes (`D[0]`, `D[2]`) and changes two others (`P[1]`, `P[3]`), and the grid size cannot be changed yet. Scaling and timing are unverified.

3.3 Target Resource Footprint Guidelines

5. Project Status & Verified Evidence

What has been verified, feature 002 (`reports/002-core-dynamics-redesign/`, `specs/002-core-dynamics-redesign/design.md`):
• The `phyco-v2` reference model (`phycoweb/model_v2.py`) is integer-only and multiplierless (add, subtract, XOR, constant shifts and rotations, compare, the lut-v1 table), with golden vectors and an automated purity check. The full test suite (116 tests) passes on Windows and on Ubuntu (WSL2).
• The SP 800-22 harness `sp80022` 1.0.0 was validated against the published examples, Appendix B and NIST's own STS 2.1.2 (0 mismatches at ±1e-6), and replaces nistrng.
• Pre-registered acceptance attempt 1 (held-out seeds never used in tuning; 100 sequences of 2²¹ bits; both controls): verdict **PASS**. phyco-v2 passed all 15 test families, the OS-CSPRNG positive control passed, and lut-v1 failed 11 of 15 (`reports/002-core-dynamics-redesign/attempt-1/`). A re-score reproduced every p-value.

What has been verified, feature 001 (`reports/001-integer-lut-perturbation/`):
• The `lut-v1` reference model is integer-only and deterministic, with golden vectors and 31 automated tests, identical on Windows and on Ubuntu (WSL2).
• It is bit-exact with the archived floating-point model in every stage except the perturbation source.

What has not been verified, or is known to be weak:
• Statistical quality beyond SP 800-22. The PASS above means only that the SP 800-22 tests detected no defect in 100 held-out sequences. Broader batteries (PractRand, TestU01, Dieharder) have not been run. The feature-001 screening used the defective nistrng 1.2.3; see the erratum and the re-score table in `reports/001-integer-lut-perturbation/summary.md`. lut-v1 fails SP 800-22 under the feature-002 protocol.
• Cryptographic security: none. No cryptographic analysis or independent review exists. lut-v1's output exposes the low 8 bits of each vein value. phyco-v2 has 272 bits of state, no keying and no cryptanalysis, and its update uses generic add-rotate-XOR operations.
• Hardware: no VHDL, testbench or synthesis result exists yet. phyco-v2 has open RTL items (a fixed 2×2 ring, a long combinational path per step); see the design review in `specs/002-core-dynamics-redesign/plan.md`.

Do not use PhycoWeb-PRNG for secrets. phyco-v2 passing NIST SP 800-22 shows only that no statistical defect was detected by those tests. It does not show cryptographic security.
